# 图像准备方案入口与多机安排

当前操作规则由[数据准备](../../data/preparation.md)维护，字段与空间对应由[数据合同](../../architecture/data_contract.md)维护，`processed/<study>/`文件布局由[存储规范](../../architecture/storage.md#准备产物文件布局)维护。

执行顺序为：全局marker语义统一 → study/panel清理与index → 逐image共享强度 → mask → 细胞表与定量 → neighbors → crop对应 → study汇总保存。实际完成情况见[项目状态](../status.md)。

以下保留多机核验记录及调度建议，参数通过实施时的吞吐检查确定。

## 5. 多机资源与任务分配

以下为2026-10-20已有只读核验记录；运行前确认可用显存、远端环境及传输吞吐。

|主机|GPU|内存|建议角色|
|---|---|---:|---|
|当前宿主|RTX4090 24GB ×1|125GiB|NAS I/O、归一化、定量、索引、唯一发布；辅助分割|
|10.26.65.226|驱动报告 RTX4090 约48GB ×2|125GiB|优先分割，NVMe 临时缓存|
|59.77.5.73|RTX3090 24GB ×2|503GiB|第二组分割 worker|
|59.77.5.72|RTX2080Ti 11GB ×4|503GiB|兼容性与吞吐通过后参与|

226迁移后的授权重连已通过临时known_hosts完成。三台远端尚未确认项目 NAS 挂载，73的 /mnt/NAS_21T 实际是根分区普通目录。网络吞吐与远端 Cellpose 环境未实测。

建议每 GPU 一个常驻进程，主控按图分发，避免同一图被重复领取；每次尝试有唯一身份，主控只接收仍有效尝试，超时回收后迟到结果不覆盖新产物。主机准备两通道分割输入 TIFF+JSON，远端暂存、回传 mask TIFF 与实际参数 JSON；其余蛋白不传输。大图分块数据保留原图范围与 halo。已有 mask 的图像绕过 GPU。

初始 NAS 读取队列1–2路、GPU worker CPU上限4线程、主控CPU计算上限8线程、每GPU最多预取下一项；按一次吞吐检查调整。2080Ti需单独检查精度/显存，从 FP32 与较小batch验证，不能直接复制 BF16 配置。远端缓存容量有上限；主控接收有效结果后释放对应可重建缓存。正式图像文件单写入者，study index由主控单写。
