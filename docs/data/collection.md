# 公开空间蛋白数据收集

本页维护收集要求、study 覆盖判定、候选与资源表，以及 agent 工作流。训练就绪层级见[catalog.md](catalog.md)，训练前处理见[preparation.md](preparation.md)，存储归属见[storage.md](../architecture/storage.md)。

## 1. 收集要求

- V1 收集人类肿瘤及其配对癌旁、正常对照，以及独立正常组织；排除其他非肿瘤疾病研究。要求 study 超过 5 张独立图像；混合物种研究仅收集确认的人类部分。
- 同一 study 的合格人类成像范围至少包含 5 位独立患者/供者，跨 panel、切片、core 和来源不重复计人。人数未知时允许先收集，并在候选记录待核实；确认不足 5 位时排除。不以正在下载的局部范围判断整项 study 的人数。
- 按用户明确决定排除 Lin et al., Cell 2023（DOI: 10.1016/j.cell.2022.12.028；Lin2023_CyCIF_ColorectalCancer）。该 study 的 spora、HTAN 和 LSP 来源均不纳入，候选保留排除理由。
- 必要内容：保留空间强度信息的多通道图像，以及准确对应通道顺序的 marker 列表；图像内嵌的 channel–marker 元数据同样有效。
- 每个纳入的 panel 至少包含 20 个不同蛋白 marker；DNA/核染、空白、自发荧光、对照/二抗及同一蛋白的重复通道不计入。按 panel 分别判定，不以多个 panel 的并集达到门槛；同一 study 仅收集合格 panel 的图像。
- 实测混合通道保留来源名称、靶标集合和通道类型，每个混合通道按一个测量通道登记；单蛋白强度是否可分离属于后续训练适用性判断。
- 可收集内容：来源已有的 pixel size、患者/样本信息、cell mask、坐标、cell-by-marker matrix、细胞类型和临床资料；这些内容不作为开始下载或必要内容收集完成的条件。
- 图像按独立 ROI、FOV、组织图或 TMA 组织 core 计数。整片扫描后导出的每个独立组织 core 计一张，保留 core 标识及所属扫描的对应关系；同一 core 的重复裁剪、格式副本和通道文件不增加数量，同一覆盖范围不同时按整片与 core 重复计数。
- 发现时可依据来源清单判断规模；下载完毕时至少有 6 张完整、可读取的人类图像及对应 marker。
- 完整来源文件中缺少必要蛋白记录的采集保留原文件和缺口说明，不计入完整图像数；已确认的来源缺陷不通过重复下载相同完整文件解决。其余合格内容的收集完成单独判断，实际传输、解析或必要蛋白通道读取失败继续补缺。
- 来源版本已绑定、原 panel 全部蛋白通道的载荷边界完整、顺序明确且逐通道实读通过时，非必要核染或空白通道的来源缺口单独记录。按实际完整蛋白视图登记，保留原文件和完整原始 marker 列表。
- 收集完成与训练就绪分别判断。原生空间强度、坐标和准确通道顺序已明确时，可先收集；跨周期配准、拼接、dearray、尺度补齐、分割、归一化和患者划分属于后续数据准备。独立 core 尚未对应时保留计数缺口，不以 tile、周期或通道数代替图像数。
- 已知范围的必要图像与 marker 全部完成，且已确认的独立图像至少 6 张时，可登记下载完毕；独立身份未明的成员保留但不计数，继续记录对应缺口。

逐 study 确认疾病范围与优先级、独立患者/供者数、各 panel 的不同蛋白 marker 数，以及独立图像/core 数。人数、样本数和 core 数分别记录；人数门槛为至少 5 位，图像门槛为超过 5 张，蛋白门槛为各 panel 至少 20 个不同蛋白。

| 收集优先级 | 范围与处理 |
| --- | --- |
| 优先完成 | 肿瘤及其配对癌旁、正常对照，保留研究内部对应关系 |
| 保留收集 | 正常免疫组织及其他合格正常组织 |
| 排除 | 其他非肿瘤疾病研究，包括糖尿病、COVID-19、GVHD、移植排斥、炎症性疾病及神经退行性疾病；停止任务，删除本地数据及候选、资源表记录 |

混合研究按可区分的成像队列判断，保留肿瘤及其配对对照、正常组织；疾病身份未明时先核对对应，不能仅凭 study 名称删除整项研究。疾病排除记录保存在收集运行目录的 scope 清单，供调度与唯一汇总过滤历史任务、旧报告和重复发现。

## 2. study 覆盖判定

一个原始数据生成 study 对应资源表一行。spora、HTAN、HuBMAP 及 VirTues/KRONOS 使用的数据集合均需对应到具体 study。

通过原论文、DOI、数据说明和来源引用确认身份。同一研究的发布版本、镜像和纯复用论文归入同一 study；产生新成像数据的研究单独记录。同一 study 的多个 cohort、panel 和平台保留内部对应关系。

| 已有覆盖 | 处理 |
| --- | --- |
| study 及所需内容已覆盖 | 更新候选结果，跳过重复下载 |
| study 已有，其他来源提供缺失内容 | 补充图像、marker、mask 或 metadata，更新原记录 |
| 尚未收集该 study | 执行逐 study 收集流程 |

按来源的图像/样本编号和文件说明核对覆盖范围；同一 study 跨来源仅对确认不同的图像增加计数。身份或覆盖范围未明的来源继续在候选中核查。患者重叠本身不等于研究或图像重复，相关信息保留供后续划分使用。

已有 spora 原生数据满足要求时直接使用。全量哈希和图像相似性扫描不作为常规收集步骤；具体文件疑点按需核查。

## 3. 候选与资源表

候选唯一维护于 NAS metadata/public/candidates.csv，沿用原 MASTER_INVENTORY 的 16 列。原 Excel 保留为历史参考；候选行是 study 或大型来源线索，多个来源可对应同一 study。

使用候选已有列记录处理：URL 保存来源，Access_status 记录访问情况，Duplicate_status 记录对应的已有 study，Next_step 记录负责人、本次范围、结果和下一步。新增 study 加入候选，已覆盖、等待和技术条件不符合的记录保留；已确认排除的其他疾病研究不保留在候选表。

人数核对结果写入现有 Patient_count，明确下界用 >=N，未知留空；依据与待核实事项写入 Next_step，收集优先级使用现有 Priority。主控复核依据保存在 NAS metadata/public/patient_eligibility_review.json；唯一汇总更新下载进度时保留这些裁定和待核实说明。资源表不增加人数或优先级列。

最终资源表保存为 NAS metadata/public/studies.csv，每个已确定收集的 study 一行，固定以下 15 列：

dataset_name,year,paper_doi,species,technology,tissue,disease,source_url,status,n_images,image_path,marker_path,mask_path,meta_path,meta_info

| 字段 | 填写规则 |
| --- | --- |
| dataset_name | 汇总 agent 按第一作者姓氏年份_技术_疾病或癌种命名；作者或年份缺失时沿用候选 Canonical_ID。登记后保持名称稳定，同名不同研究加 a/b，多平台或多疾病可用 MultiPlatform/MultiDisease |
| year, paper_doi | 原始研究发表年份和 DOI |
| species, technology, tissue, disease | 实际收集内容的物种、技术、组织和疾病 |
| source_url | 实际选用的下载来源 |
| status | 仅使用待下载、下载完毕；必要内容的部分下载、等待审批及补缺均为待下载 |
| n_images | 本地完整下载且可读取的图像实际数；未下载为 0，中断文件不计数。marker 暂缺时仍填写实际图像数 |
| image_path, marker_path, mask_path, meta_path | 实际存在的 NAS 相对文件或目录路径；marker 内嵌时 marker_path 指向含该元数据的图像文件或目录，没有则留空 |
| meta_info | 实际 metadata 的字段名称，例如 patient_id;age;stage;treatment;response |

CSV 使用 UTF-8 和标准 CSV 转义，多值以分号分隔，未知值留空。等待原因和任务进度写回候选，资源表保持上述 15 列。确认不符合收集范围的 study 从资源表移出；其他疾病研究同时删除候选记录，其余技术条件排除仍在候选保留原因和依据。

所有技术统一执行以下清理：删除 NAS 项目内已确认排除的其他疾病 study、蛋白 marker 不足 20 的 panel 数据，以及合格成像队列确认不足 5 位患者/供者、或合格独立采集总数不超过 5 的 study 数据，包括对应下载暂存。混合 panel 仅删除不合格部分；先停止相关写入、取消续传及后续处理，核对文件归属，再清理并更新路径。保留用于证明排除结论的少量来源说明和检查记录。人数和图像数按确认可收集的完整范围判断，下载中的局部数量不作为排除依据；人数未知允许先收集。

## 4. NAS 组织

dataset_name 对应存储规范中的 dataset_id。来源文件保存在 raw/{public,private}/<dataset_name>/<source_release>/，保留原生图像、marker、mask 和 metadata。受限数据按批准范围访问。

需要从来源说明提取的 marker 或文件对应信息保存在 metadata/{public,private}/<dataset_name>/；已有可用文件直接引用。多 panel 保留各自 channel–marker 关系，路径列可登记多个来源位置。

原始发布文件不原位覆盖，不为目录统一重复复制大型图像。资源表登记非敏感概况和路径，患者级资料保留在 NAS 原文件中；SSD 文档记录规则、总体进度和 NAS 入口。

## 5. agent 与任务所有权

整体主控协调两条并行工作流，各设一个通过 codex-cli 调用的 gpt-6.1-sol/high 主控。候选主控分配检索范围，派发至少 5 个 gpt-5.6-luna/max agent，复核其检索与可及性证据，再通过唯一汇总流程更新候选表。下载主控接续现有下载负责人和断点，安排合格范围的本地化。两条线的辅助 agent 及其 subagent 均通过 codex-cli 使用 gpt-5.6-luna/max，数量不限。

- 两条线的主控：codex exec -m gpt-6.1-sol -c 'model_reasoning_effort="high"' -
- 被控 agent / subagent：codex exec -m gpt-5.6-luna -c 'model_reasoning_effort="max"' -

每次调用明确来源或 study 批次、交付内容和写入范围。父 agent 跟踪并收束所属 CLI 子进程后交接任务。

已确认的长时间下载和增量汇总可由独立受管服务执行，登记负责人、命令、日志与退出状态。agent 负责确认、修正和复核；模型会话退出不终止已交给服务的下载，同一 study 仍只有一个执行负责人。

已确认合格且必要内容可及的未本地化范围统一进入后台下载/续传队列，复用现任负责人、完整文件和断点。下载队列独立推进，图像检查与表格整理后续统一进行；单项检查不阻塞其他已确认范围的下载。后台记录传输状态，资源表沿用已验证的图像数和完成状态。

汇总 agent 是候选 CSV 和资源 CSV 的唯一写入者，在最新内容上合并各 agent 的增量结果。同一 study 同时只有一个下载负责人；subagent 的文件写入范围由负责人分配。发现 agent 提交新线索，由汇总 agent 交给现任负责人。

执行中确认两个任务属于同一 study 时，先停止重复任务及其子进程，再交接已有文件。恢复中断任务前确认旧进程已停止，核对已有文件并续传或补缺。

## 6. 工作流 A：持续发现与更新候选

1. 从候选 CSV、Zotero spatial protein 分类、相关论文和公共数据入口发现 study。
   - 交付：原始研究、数据入口及人类/规模线索；明确属于其他非肿瘤疾病的研究不加入候选。
2. 与现有候选和资源表匹配；新 study 加入候选，同一 study 补充来源。
   - 交付：由汇总 agent 合并的候选增量，保留已有处理结果和负责人。
3. 将未领取的 study 交给工作流 B，将新线索交给已有负责人，并继续下一批发现。
   - 交付：持续更新的候选列表及本轮已检索范围。

本流程与工作流 B 同时运行；单个入口不可读取时记录该项，其他入口继续处理。

## 7. 工作流 B：大型来源优先，逐 study 确认、下载与补缺

启动顺序：

1. 优先处理 spora、VirTues、KRONOS、HTAN、CellTuneDepot 和 GigaTIME；按以下逐 study 流程确认并下载可取得的内容。CANVAS 已申请，获批后加入。
2. 将首批本地内容按原始 study 汇总，合并重复来源并登记覆盖范围。等待审批或必要内容不可及的来源记录原因后继续其他候选。
3. 以已有覆盖为基础，逐步添加其余候选 study；工作流 A 全程并行补充候选。

逐 study 流程：

1. 领取：汇总 agent 分配具体 study，记录负责人。
   - 确认：负责人取得已有来源和本地资源信息。
2. 准入：定位原始研究，根据来源说明或文件清单确认人类部分、疾病范围与收集优先级、独立患者/供者数、各 panel 至少 20 个不同蛋白 marker、合格 panel 合计超过 5 张独立图像/core 及 marker 对应。
   - 确认：其他疾病研究记录排除结论并从候选移除；已知人数不足 5 或其他技术条件不符的写回候选并结束。人数未知可先收集并继续核实，图像和 marker 必要信息未明的记录具体缺口，继续其他候选。
3. 覆盖：核对资源表、NAS 和已分配任务，决定已覆盖、补缺或新增，将本次必要内容范围写入候选 Next_step。
   - 确认：已覆盖的经第 6–7 步检查、登记后结束，已有检查结果可复用；其余明确需要下载的新增图像和 marker。
4. 可及性：确认所需 image 和 marker 的实际入口、通道对应及访问条件；可读取少量清单或图像头确认内嵌 marker。
   - 确认：必要内容可获取且覆盖范围明确后，由汇总 agent 登记待下载及已有实际数量、路径，随即下载；访问受阻或等待审批时写回候选，已确定收集的 study 登记待下载及已有实际数量、路径，释放负责人。
5. 下载：确认 NAS 挂载和空间，按来源结构下载本次新增内容，保持图像与各 panel 的 marker 对应；配套资料有则收集。
   - 确认：满足第 2–4 步即安排后台下载/续传；已完成文件保留，中断文件续传或补齐。交接保存传输结果和断点，其他任务继续下载。
6. 统一检查：下载后批量确认传输完成，逐图像打开结构并读取有效区域，核对 channel–marker；已有 mask 直接沿用来源提供的 image-level 对应及尺寸、配准说明，整理实际 metadata，不重复确认已有图像—mask 配对。
   - 确认：按本地文件计算 n_images；可选资料缺失或不能可靠对应时在候选记录，相应资源路径留空。
7. 写回：先更新 15 列资源 CSV，再回写候选；本次必要内容完成、实际图像至少 6 张且 marker 对应明确时标记下载完毕。
   - 确认：人数未知不阻碍下载完成状态，候选保留待核实；确认不足 5 位时从资源表移出。必要内容未完成时保持待下载和实际数量；写回中断时依据本地文件补齐表格，不重复下载已完成文件。
8. 结束与补缺：本次范围完成即交接；新增来源作为后续补缺任务，确认新增必要内容后重新领取并改为待下载，保留已有数量和路径。
   - 确认：未核实的新来源及待补可选资料留在候选，不重置必要内容已完成的状态。

## 8. 交接

每个已下载 study 应能通过资源表定位图像、marker 和可用配套资料，并复算 n_images。每个本轮处理的候选应有结果或具体下一步；等待事项不占用下载负责人。项目进度写入 status.md。
