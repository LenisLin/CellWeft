# Per-study输入的独立校对与修补

独立复核者校对，主控核实并派发修补，整理者修补，独立复核者复查，主控验收。检查规则使用[review_checks.csv](templates/study_input/review_checks.csv)，结果使用[review_results.csv](templates/study_input/review_results.csv)。

2026-10-25按用户要求采用study级分层抽样。全量执行可自动化的结构、外键、版本和文件头检查；来源人工对照、概览及独立像素重算按第3节抽样。同一规则、同一来源版本的既有证据复用；不再逐图派发重数值复核。此策略同时衔接[下游抽样验收](preparation.md#6-io资源与完成检查)。

2026-11-02用户明确临床信息对应不是技术预处理硬性要求。M01改为`metadata_linkage`：缺少临床值、patient桥接或跨image生物学sample归并依据时，保留空值及unresolved事实，限制依赖该连接的用途；图像来源、panel、采集框、有效域及物理区域拆分按I01–I05独立判断。未知sample关系不能用图像编号或论文人数补全，也不据此阻断已经独立确认的图像技术范围。D01仍须明确绑定实际image及其用途限制；已知像素、通道或几何错误继续阻断对应范围。此规则取代下文Tu29历史决定中“其他study仍须单独申请患者缺口例外”的执行限制。

## 1. 独立校对

1. **取得输入。** 读取image、sample、panel、字段映射及图像文件，直接取得对应原始图像、S1、区域表和临床来源表。记录study、preparer和reviewer，整理者与复核者使用不同任务身份。
2. **检查来源与结构。** 按S01、I01–I04、M01全量自动检查来源对象清单、主键、image/sample外键、区域标签、框及padding几何；逐条来源身份和区域归属的人工对照按第3节抽样，并核实全部不同连接规则。纳入信号和代表性概览依据按[输入流程](study_input.md)核对。
   可选生物学区域分类有来源冲突时，按输入流程第3步核对原值保留、逐image冲突状态、证据引用及明确分析禁用范围。I04的来源转录和物理区域结论分别记录，生物学分类仍记unresolved；只有身份、几何与有效域独立成立，且冲突不影响这些条件时，才可确认该范围的物理输入。将标签置空或仅改写旧阻断记录不能代替metadata修补与独立复查。D01同时引用未决分类证据及使用限制，分类本身不能据此标为已验证。
3. **检查panel及文件。** 按P01–P03重查来源顺序、S1对应、通道取舍及输出位置。逐image打开TIFF头，核对尺寸、dtype、通道数、标准化名称和顺序。
   `output_channel_index`按数值排序；CSV按字符串读入时先验证并转换该列，再比较OME名称及对应来源像素。核验程序的排序或类型解析出错时，先修正核验并重查原产物，在details保留原误判和重查证据，再确定实际修补范围。
4. **抽查像素。** 按第3节执行I05，核对来源与输出的保留通道值、dtype、padding和采集有效域，记录图像、通道及坐标。
5. **核对临床值。** 按M02及[临床规则](templates/study_input/clinical_rules.csv)核实每种不同连接和转换规则的语义；全表自动检查唯一性、类型、单位、连接覆盖及已知冲突，人工来源对照每种规则抽查至多3条，覆盖实际存在的缺失、零值、时间或删失分支。异常按受影响规则扩查。缺失及未确认语义保留原blocking_scope。
   M01另核对本地及公开来源追查记录、sample表实际行数、image→sample与sample→patient覆盖。空表或身份连接缺口记为unresolved，并在D01分别报告图像完成范围与metadata缺口；图像通过的检查保持有效。sample_region存在时，全量自动检查标签、几何及坐标，来源边界、邻sample分离及目标覆盖的概览按拆分类型抽样。
6. **提交修补项。** 每条差异定位check_id、记录键、来源和目标，说明实际差异；主控按第2节派发修补任务。

## 2. 确认问题、持续修复与批准后排除

1. **独立确认。** 回查实际文件、现行要求与既有证据，独立复核疑点。问题确认后立即按数据集报告，定位image、具体问题及未达到的要求；合并同一原因，确定受影响记录、修复动作与通过条件。已有正确结果及有效依据复用，已核实的可选来源缺失以空值和说明确认。
2. **持续修复。** 可以修复的，按下表修复对应产物及直接依赖，执行必要的针对性独立复查与正式接收，同步逐图公共metadata及受影响索引、计数。一次尝试失败不直接判为不可修复；每次根据实际原因决定下一项修复，正确产物不重复计算，管理字段或组成员改变不引发整批重新验收。
3. **待解决与排除申请。** 尚待必要信息的图像记为“待解决”。当前无法修复时，列明具体image、问题证据、已尝试方法、无法修复原因和拟删除的精确文件范围，提交用户批准。未经批准保留该范围，不记为已排除。
4. **批准后执行与验收。** 获得批准后按精确范围删除，移除有效处理入口和当前范围、更新计数，并保留排除原因及批准记录；原始来源或共享资源仅在明确批准范围内删除。规定产物齐全、对应正确且正式接收后计技术完成；部分完成逐图列出缺项。输入D01与下游完整产物接收分别记录，已确认的未受影响范围保持有效。

2026-11-06用户要求替代旧“最多两轮修补”限制。已批准删除的20张已完成清理并退出当前范围，其既有证据直接复用。

| 实际差异 | 修补与复查范围 |
| --- | --- |
| 临床值、sample关联、区域注释或转换 | 修改对应metadata及field_mapping，复查受影响连接和字段 |
| 通道身份、名称、取舍或顺序 | 修改panel_mapping；实际保存的标签、集合或顺序变化时同步相关TIFF及image记录 |
| 区域框、padding、采集有效域或像素 | 更新对应image文件及metadata，复查几何和像素 |

details记录每次修复的原因、动作、修改位置及复查结论。问题由`scope + record_id + check_id`定位，同一检查中的多项差异在details中编号。最终逐图验收字段与范围见[执行与验收合同](preparation.md#执行与验收合同)。

## 3. Study级分层抽样

1. 每study起始选择3张，少于3张时全查：一张典型面积图、一张最大图、一张从其余图中固定种子随机选择的图；重复选择时补足不同image。按source_format、source_axes、panel_id、split_method及dtype分组，每组至少一张，未覆盖的组追加代表图，因此3张不是上限。另覆盖实际存在的padding、未采集范围、多文件通道及Z／时间层选择；一种情况可由同一张图覆盖。选择及补选顺序固定，记录种子和实际image列表。
2. 每张抽查image比较全部保留通道，选一个含信号的内部块和一个边界块，每块不超过64×64；按来源与输出坐标逐值比较并核对dtype。
3. 有padding、来源未采集位置或sample拆分时，检查对应区域、有效域及概览。发现差异时先冻结受影响分组，追加至多3张同组图定位；确认系统性错误则对该组全量修补和自动检查，再独立抽样复查。尚不能界定影响范围时保留该组pending，其他已通过组继续交付；已知错误不会因未被抽中而放行。
4. 将分组、image_id、通道位置、坐标及实际版本写入details的`study_qc`：`policy_id=study_stratified_v1`、stage、strata、sample_ids、selection_seed、evidence_paths、result及anomaly_scope。全部image检查结构和头信息，逐值像素及概览结论对应实际抽查范围。已有当前版本证据可覆盖对应样本，不为凑新样本重复读取。
5. 同组新增图像通过全量轻检查后可沿用该组独立抽样结论，不为每批新增图像重抽3张。新增格式、panel、拆分方式、dtype、来源规则或科学处理版本时仅补查受影响组；其他组结论保持。抽样尚未完成的组保留pending，复核者完成后才为明确范围写D01。

## 4. 结果填写

| result | 填写条件 |
| --- | --- |
| pass | 记录范围内符合规则；已确认的可选来源缺失以空值及说明通过 |
| fail | 已定位具体差异，记录修补动作和复查结果 |
| unresolved | 具体必要证据仍缺，记录原因、影响范围及主控处理结论 |
| not_applicable | 适用条件不存在，填写理由 |

每条结果填写scope、record_id、check_id及来源与输出位置；影响阶段按check_id连接review_checks.blocking_scope。review_results.csv保存到processed/<study>/。

任务参数为study、preparer、reviewer、input_root及本页路径。主控接收校对结果后连续组织修补、复查和验收。


## Tu29限定技术准入（2026-10-29用户批准）

仅适用于`Tu2026_PhenoCycler_Neuroblastoma`既有29张、已独立确认标本身份及原生图像的冻结范围。用户批准“仅Tu29进入技术后处理”：患者crosswalk仍缺时，M01可在该明确范围按已确认的生物学标本连接关闭技术输入阻断，D01只授予技术处理；患者缺口另以M02 unresolved及D01结构化使用限制保留。全局M01模板与其他study的身份准入规则保持。

独立复核须重核授权范围、原始来源和既有证据版本、29条image→sample连接及全部空patient_key；四张输入表和所有原生资产保持原值。允许归一化、作者mask检查或既定cpsam_v2、定量、细胞索引、邻域及crop对应。禁止患者划分、患者级临床分析、患者人数推断、前后配对结论和训练准入。组织与分割质量分别记录，技术产物完成不解除上述限制。D01保存具体image_ids、input_binding、原独立核验引用、用户批准和use_restrictions；下游交付保留完整review与sample表，训练及患者级消费者须先读取使用限制。

## 5. 程序消费的验收绑定

完成上述独立核对后，D01的details使用JSON保存`input_binding`及文字说明。`inputs.input_binding(study_root, data_root, image_ids)`生成明确image列表、完整选中image记录、实际panel输入字段、图像／有效域／可选sample区域文件size和mtime_ns、sample及字段映射版本；该函数只生成待核对证据，不写pass。复核者确认对应范围后将其写入现有review_results.csv的D01通过记录；写入或撤销验收时持有study级resource_lock独占锁，以临时CSV替换正式记录。逐图直接消费在同一study读锁内重新检查当前D01及阻断项，持锁完成该图。分布式执行允许在study及input读锁内逐字节暂存并核对版本，随后释放输入锁、在不可变副本上计算；发布时重新取得共享NAS名额、study及input读锁，复核D01与完整科学请求，任一依赖变化即拒绝发布。NAS名额先于study/input锁获取，避免与上游发布锁顺序相反。更新输入后旧绑定失效，按实际修改范围复查并重新绑定。embedding_row及向量映射不进入像素输入版本。

抽样通过后，独立复核者可绑定同组全量轻检查通过的明确image范围；D01同时记录`study_qc`及其证据，区分绑定范围与实际重核样本。主控不据策略文件自动生成科学pass，也不把未抽样图像记为逐像素独审通过。

消费端须区分结构化绑定与闭合说明行。没有`input_binding`的闭合说明仅在`technical_only=true`、`superseded_by`指向同scope当前通过的结构化绑定、且`closed_actual_scope_image_ids`非空、唯一并完全被该绑定覆盖时作为说明忽略；它不贡献任何准入image。最新撤销记录仍覆盖旧pass；畸形`input_binding`、悬空引用或越界范围仍拒绝，不据说明补造绑定。

程序只消费与当前完整绑定一致的D01 pass；同一scope/record_id/check_id以后写入的结果覆盖前次结论。输入阻断项仍为fail／unresolved时不放行；部分范围的问题可在details JSON以`image_ids`明确受影响范围，未声明范围的阻断项影响整个study。M01连接缺口及M02临床分析缺口按各自blocking_scope保留；不把这些缺口改写成身份已确认。D01对缺少sample/patient依据的范围记录患者级划分、临床分析、配对及跨image归并限制；训练用途另按组织及数据划分合同核验。旧自然语言范围记录继续作为人工证据，不能被程序推断为全study准入。

输入metadata的扩展列保留；field_mapping对应target_table=image_metadata、target_field的notes使用JSON明确`data_type`（string/integer/number/boolean）、`definition`及适用单位。程序校验类型和来源定义，不删除扩展列。来源适配器可省略可选基础字段，发布时补空；正式交付必须包含全部39个基础字段。
